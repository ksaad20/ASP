# Security Policy

Thank you for helping improve the security of **Autonomous Synthesis Planner (ASP)**.

The project values responsible disclosure of security vulnerabilities and aims to address legitimate security issues in a timely and transparent manner.

---

# Supported Versions

Security updates are provided for actively maintained releases.

| Version                 |  Supported  |
| ----------------------- | :---------: |
| Latest release          |      ✅      |
| Previous stable release |      ✅      |
| Older releases          |      ❌      |
| Development branches    | Best effort |

Users are encouraged to upgrade to the latest stable release whenever possible.

---

# Reporting a Security Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues.**

Instead, report vulnerabilities privately to the project maintainers.

A report should include, where applicable:

* Description of the vulnerability
* Affected version(s)
* Steps to reproduce
* Potential impact
* Proof of concept (if available)
* Suggested mitigation (optional)

Providing clear reproduction steps helps us investigate and resolve issues more efficiently.

---

# Response Process

When a valid security report is received, the project aims to:

1. Acknowledge receipt of the report.
2. Assess the severity and impact.
3. Reproduce the issue.
4. Develop and test a fix.
5. Publish a patched release when appropriate.
6. Document the security update in the project changelog.

The exact response timeline depends on the complexity and severity of the issue.

---

# Coordinated Disclosure

We encourage responsible disclosure.

Please allow maintainers a reasonable opportunity to investigate and address reported vulnerabilities before publicly disclosing technical details.

This helps protect users while a fix is being developed and released.

---

# Scope

The security policy applies to:

* Python package
* Command-line interface (CLI)
* Public API
* Build configuration
* Dependency management
* Documentation examples
* Release artifacts

The following are generally **out of scope** unless they introduce a direct security risk:

* Typographical errors
* Documentation formatting issues
* Performance optimizations
* Feature requests
* Unsupported third-party modifications

---

# Dependency Security

The project strives to:

* Keep dependencies up to date.
* Minimize unnecessary dependencies.
* Monitor for known vulnerabilities.
* Apply security patches in supported releases.

Contributors are encouraged to avoid introducing unnecessary packages and to justify new dependencies in pull requests.

---

# Secure Development Practices

The project follows modern software engineering practices, including:

* Code review
* Automated testing
* Static analysis
* Dependency management
* Continuous integration
* Type checking
* Reproducible builds

These practices help reduce the likelihood of introducing security-related defects.

---

# Reporting False Positives

If you believe a reported issue is a false positive or no longer applicable, please provide supporting technical evidence so maintainers can review the report appropriately.

---

# Acknowledgements

We appreciate researchers and community members who responsibly disclose security vulnerabilities and contribute to improving the reliability and safety of Autonomous Synthesis Planner.

Your efforts help strengthen the project for everyone.

---

# Security Philosophy

Autonomous Synthesis Planner is developed as an open scientific software platform.

Security, transparency, reproducibility, and maintainability are considered essential components of trustworthy scientific software.

While no software can guarantee the absence of vulnerabilities, the project is committed to continuous improvement through responsible development and community collaboration.
